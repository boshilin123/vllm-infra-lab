# Short 当前 GPU 校准：c8-mns8

## 实验目的

在回退到单副本 `max-num-seqs=8` 后，用当前 Pod 所在的物理 GPU 1 重新执行 256/128 Short 场景。该结果是随后 Prefill/Decode 对照的同卡、相邻时间窗口基线，避免直接拿历史物理 GPU 3 的 c8 数据充当严格对照。

## 实验配置

- 模型：Qwen3-8B BF16，vLLM 0.9.1
- 输入/输出长度：256/128 tokens
- 客户端并发 / 服务端 `max-num-seqs`：8/8
- `max-model-len` / `gpu-memory-utilization`：4096/0.85
- 每轮预热/正式请求：10/100，正式重复 3 次
- 节点与物理 GPU：qhvgpu1 / GPU 1
- GPU UUID：`GPU-5e5590e5-51de-1c1c-6c72-4cbe1477e116`
- Git commit：`da604fe15147b72a7341b7370eef168eef1d8c05`
- 正式随机种子：`7042/7043/7044`

## 服务端与 GPU 观测

正式阶段主要观察到 `running=8、waiting=0`，KV Cache 峰值约 13.52%，与 `8 × (256+128) / 22832 ≈ 13.46%` 的满长度上界接近。GPU-Util 约 96%–100%，实验窗口内未观察到请求失败或服务中断。

该校准值的输出吞吐比历史 GPU 3 c8 的 178.796 tok/s 高约 1.04%。差异可能来自 GPU 个体、Pod 重建、共享环境和测量时间，不应包装成参数优化收益；后续四场景比较只使用本次同卡基线。

## 结论

- 当前 GPU 上的 c8-mns8 Short 基线通过全部 Short SLO，可作为三组长负载的严格相邻对照。
- KV Cache 容量不是 Short 场景瓶颈；GPU 很忙也不等于已经找到全局吞吐峰值。
- 主要吞吐与 E2E 重复性较好，但 TTFT 的跨轮波动更明显，后续应同时报告中位 P95 和 CV。
