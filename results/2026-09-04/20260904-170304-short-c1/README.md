# Short 场景：并发 1 基线

## 实验目的

建立 Qwen3-8B 在单副本、单张 NVIDIA A10 上的并发 1 基线，为后续并发 2、4、8、16 的饱和点实验提供对照。

## 实验配置

- 输入长度：256 tokens
- 输出长度：128 tokens
- 并发：1
- 每轮预热请求：10
- 每轮正式请求：100
- 正式实验重复：3 次
- vLLM：0.9.1
- 服务节点：qhvgpu1
- 宿主机物理 GPU：3
- GPU UUID：`GPU-c9ee2ea8-993d-e7e2-7e3f-7a183b63d573`
- Git commit：`2193547630d797647c8b41a086e2ed7549ea3c55`

完整配置以 `metadata.yaml` 为准，汇总统计以 `summary.csv` 和 `aggregate.json` 为准。

## 三轮中位结果

| 指标 | 中位数 |
| --- | ---: |
| 请求吞吐 | 0.221521 req/s |
| 输出 Token 吞吐 | 28.354627 tok/s |
| 总 Token 吞吐 | 85.063881 tok/s |
| Mean TTFT | 73.899712 ms |
| Mean TPOT | 34.963472 ms |
| Mean E2E | 4513.756706 ms |
| P95 E2E | 4528.058606 ms |

三轮正式实验均为 100/100 请求成功，输入与输出长度符合场景定义。

## 一致性检查

请求吞吐可以由请求数和总时长复算：

```text
100 requests / 451.43 seconds ≈ 0.2215 requests/s
```

输出吞吐可以由请求吞吐和单请求输出长度复算：

```text
0.2215 requests/s × 128 tokens/request ≈ 28.35 tokens/s
```

端到端延迟也与 TTFT、TPOT 和输出长度一致：

```text
E2E ≈ TTFT + (128 - 1) × TPOT ≈ 4514 ms
```

请求吞吐 CV 为 0.0247%，Mean TTFT CV 为 0.69%，三轮结果在当前实验条件下具有较好的重复性。

## 当前结论与边界

并发 1 时请求顺序执行，因此请求吞吐主要受单请求约 4.51 秒的端到端延迟限制。低 CV 说明本轮重复结果接近，但不能证明其他并发、模型、GPU、节点或时间段同样稳定，也不能单独证明客户端和网络不存在系统性瓶颈。

压测客户端与服务端位于同一节点，并通过 `kubectl port-forward` 通信；该结果适合作为本项目内部对照基线，不直接代表跨节点或生产网关场景的性能。

## 下一实验的事前假设

在查看并发 2 的结果之前，先记录方向性假设：

- 请求吞吐：上升，但预计不会严格翻倍。
- 输出 Token 吞吐：上升，因为 Continuous Batching 能提高总体处理效率。
- TTFT：可能小幅上升或基本不变；并发 2 仍低于 `max-num-seqs=8`，未必产生明显服务端排队。
- TPOT：预计上升，因为两个序列共享单张 GPU 的每个 Decode 步骤。
- E2E：预计上升，128-token 输出下 TPOT 的累积影响占主导。

以上均为待验证假设，不作为实验结论。若结果与假设相反，应结合 vLLM 的 running/waiting requests、KV Cache 和 GPU 指标解释原因，而不能修改原假设以迎合结果。
